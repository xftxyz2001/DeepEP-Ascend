# 测试性能与同类实现对照

## 测试入口与已有覆盖

`tests/ep/test_ep.py` 使用 torch multiprocessing spawn，每进程初始化 NPU/HCCL，并执行 reference 对照。默认模式枚举为 alignment `{128,1}` × BF16/FP8 × bias `{0,1,2}`，其中 FP8 再覆盖 SF 行/列主序，因此基础矩阵为 18 种模式；还包含 cached、无 weights、确定性等条件检查。见 [tests/ep/test_ep.py:25](../tests/ep/test_ep.py)。

| 检查 | 源码覆盖内容 |
| --- | --- |
| dispatch hidden/SF | expanded slots 取回后与 reference 精确比对，FP8 以字节检查 |
| metadata | source id、有效 slot、唯一性、边界、去重 rank count |
| expert count | 实际 count、CPU list 对齐长度、累计统计 |
| padding | x/SF 清零，cached 路径还检查 weights padding |
| combine | 与匹配局部归约的 reference `torch.equal`，恢复 weights 与原始一致 |
| cached | 更新 x/SF/weights，保持原 handle 和 routing 映射不变 |
| optional weights | 有/无权重返回路径 |
| deterministic | 重复 dispatch 的行序与数据一致 |

这些是测试代码中可见的检查项，不代表本地已经执行通过。当前 Windows 环境没有完成 CANN 编译、设备执行或网络拓扑验证。

## 目标服务器的运行顺序

先在满足拓扑条件的服务器做 BF16 单模式正确性，再扩展 FP8、cached、no-sync、deterministic、压力与性能。示例命令均在仓库根目录运行，且在执行前 source CANN 环境。

```bash
export EP_AVOID_RECORD_STREAM=1
export TASK_QUEUE_ENABLE=0
export HCCL_IF_BASE_PORT=48361
python tests/ep/test_ep.py --num-processes 8 --num-ai-cores 32 \
  --num-tokens 4096 --hidden 7168 --num-topk 6 --num-experts 256 \
  --dispatch-dtype bf16 --test-first-only --skip-perf-test

python tests/ep/test_ep.py --num-processes 8 --num-ai-cores 32 \
  --num-tokens 4096 --hidden 7168 --num-topk 6 --num-experts 256 \
  --dispatch-dtype fp8 --skip-perf-test

python tests/ep/test_ep.py --num-processes 8 --num-ai-cores 32 \
  --num-tokens 4096 --hidden 7168 --num-topk 6 --num-experts 256 \
  --do-cpu-sync 0 --deterministic --skip-perf-test
```

`--test-first-only` 会提前结束矩阵，不能据此声称全功能通过。`--skip-check` 会跳过正确性，不能用于验收。`--do-pressure-test` 最多循环十亿次，需主动规划运行时间；`--reuse-ep-buffer` 决定压力阶段是否复用 buffer。

仓库脚本中 `WORLD_SIZE` 是节点数，`RANK` 是节点编号，不是 torchrun 常规全局进程数/rank：

```bash
# 每节点都执行同一命令；以下为节点0，另一节点将 RANK 改为1
export MASTER_ADDR=<node0-address>
export MASTER_PORT=8361
export WORLD_SIZE=2
export RANK=0
python tests/ep/test_ep.py --num-processes 8 --skip-perf-test
```

其 global rank=`node_rank*local_processes+local_rank`。能启动多节点进程并不自动说明跨节点的 UBMEM/UBC_CTP 条件满足。见 [deep_ep/utils/envs.py:77](../deep_ep/utils/envs.py)。

## 性能口径

测试 `benchmark()` 分两轮移动 barrier：一轮 issue 包含 URMA drain，测“通信完成”和独立 epilogue；另一轮 issue 不包含 drain，测提交阶段。预热10次、正式50次、flush L2，并有通信 profiling barrier。首次 JIT 不应混入稳态性能解释。

输出里的 URMA 带宽分子沿用逻辑 tensor bytes 与去重接收数，包含 local tokens；它不是纯链路字节计数。dispatch 逻辑字节与 wire record padding/source id 不完全相同，combine 逻辑带宽又未把全部尾部 metadata 纳入。因此不能简单拿它和网卡原始线速或其他框架“端到端吞吐”比较。

本提交 README 的 EP8～EP128 数值是指定 PoC HDK、CANN、H=7168、K=6、E=256、capacity=16384、A=128、32 AI cores 条件下的项目记录，排除了最终 epilogue。复现报告应分别保留 issue、issue+drain、epilogue、端到端含专家计算的边界，不使用本次静态说明作为性能背书。

## 支持约束需要取交集

| 条件 | 当前源码依据及解释 |
| --- | --- |
| E | persistent worker `kNumExperts<=kNumThreads`，线程数512；公共数组2048不等于 EP 可用2048 |
| P | 公共上限256，但 dispatch arrival tag 只到255；多 rank 还要求偶数，因此不能宣称EP256 |
| V | launch_dispatch 要求≥16，Jetty实例要求≤64；还受设备实际 AIV 数限制 |
| K | `1≤K≤32`，还受 combine UB ring 容量限制 |
| E/P | 必须整除；copy epilogue local experts≤512 |
| A | 正2次幂，影响输出 padding 和容量 |
| H | combine Host 要求 H%128=0；dispatch zero-padding 要求 hidden bytes 对 vector zero 大小对齐，FP8 情况要独立核对 |
| M | >0，T≤M；还受24位count、INT_MAX expanded行、SQ深度与UB预算限制 |
| 多 rank | UBMEM直接可达、UBC_CTP、偶数rank、同一本地endpoint条件 |
| dtype | dispatch BF16或带SF的E4M3FN，combine BF16；不能外推FP16/FP4/MXFP8支持 |

这些是必要约束，不是所有满足条件组合都通过的充分证明。没有遍历所有shape或上板矩阵。

## 排障入口

| 现象 | 优先定位 |
| --- | --- |
| `_C` 导入失败 | setup链接库、torch_npu/CANN ABI、实际安装包路径 |
| 缺DeepJIT头文件/首次调用编译失败 | 子模块状态、CANN路径、Bisheng、EP_JIT_DEBUG与模板静态断言 |
| 无UB_MEM或UBC_CTP链接 | `get_physical_domain_size`、HCCL rank graph所选layer和channel资源 |
| `reduction timeout` | Host count通知，所有rank调用次序、路由、kernel是否到达计数阶段 |
| `DeepEP HCOMM scalar CQ poll timeout` | SQ发布、CQ owner/head、endpoint与设备运行日志 |
| `DeepEP HCOMM scalar CQE failed` | status/substatus；先记录错误，不从一个码臆断唯一根因 |
| `DeepEP barrier timeout` | 哪个rank未达barrier、是否已有上游device错误、stream依赖 |
| 结果错但无异常 | weights是否应用一次、handle/路由是否匹配、expert输出行序与有效长度 |
| 显存超出hint | recv/send/metadata/排序临时tensor，no-sync上界，workspace及大页资源 |

`EP_BUFFER_DEBUG` 在Python中按环境字符串真值判断，设置字符串 `0` 仍可能打印，关闭应 unset。`EP_JIT_*` 配置由 DeepJIT 消费；本地子模块未展开时，不能将 README 默认值当成已核验的内部实现。`EP_AVOID_RECORD_STREAM` 对Bucket是显式要求，EP source lifetime则由epilogue capture另行保护。
